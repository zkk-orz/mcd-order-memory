# 点餐全流程与场景细则

## 第一步：解析（任意格式，纯对话能力，不调工具）

三种典型形态，统一解析为 `{人: [食物+约束]}` + 忌口候选：

| 形态 | 示例 |
|---|---|
| 微信接龙 | "接龙：1. 张三 双吉套餐 2. 李四 麦辣不要辣 3. 王五 1+1可乐" |
| 群聊乱流 | "老王说他要那个板烧 李四还是1+1吧 小美不吃牛肉 大家看着办" |
| 口头转述/概括 | "部门午餐 8 人 400 块，3 个不吃辣" / "孩子想吃麦乐鸡，我爸来碗粥" |

解析要点：约束（不要辣/不吃牛肉）挂到人；"大家看着办"=缺省项由你按画像或官方搭配规则补齐并说明理由；解析失败就自然追问一句，不猜。

**速算（解析后立即执行，勿手工逐项查价）**：

```bash
python scripts/order_helper.py quote --json '{"slot":"午餐","people":[{"name":"张三","items":["双吉套餐"]},{"name":"李四","items":["板烧鸡腿堡（不辣）"]},{"name":"王五","items":["1+1可乐"]}]}'
```

一次返回每人每项的价格/卡路里/匹配说明+合计+人均（AA），未匹配项列入 unmatched（交给你追问或换名重试）。卡路里含套餐组成估算与同类估算（note 字段说明），呈现时保留 ≈ 标注。

## 实时数据源（先探测再干活，见 SKILL.md 三优先级）

1. 宿主原生 MCP 可调（WorkBuddy 连接器等）→ 工具直接原生调用；
2. 可跑脚本且有 `MCD_MCP_TOKEN` → `python scripts/mcp_client.py call ...`；
3. 都没有 → 全程快照（本流程标注【快照】的路径），价格标"快照价（日期）"。

## 主流程（到店）

1. **找店**：仅当会话内无门店码时调 `query-nearby-stores`（必填 **beType+searchType**，searchType=2 时 city 必填，keyword 辅助；beType=1 到店/5 得来速），缓存 storeCode 用全程。**实测：深夜门店打烊报 60003"门店暂停营业"→ 告知用户并换区域搜营业中的门店（businessStatus=true，24 小时店 00:00-23:59）**；
2. **配餐**【快照】：读 assets/menu-snapshot.json，避忌口、按画像、按官方团餐搭配规则（20 元以下小食；20-30 汉堡+小食或饮料；30-40 汉堡+薯条/小食+饮料；40-50 汉堡+薯条+小食+饮料；50+ 丰富组合、小食不重复），说明每项理由；
3. **定制项**（仅实时数据源可用且用户提"不要辣/换组成"）：`query-meal-detail`（需 storeCode+orderType）；
4. **省钱检查**（自动，细则读 savings.md；调用方式按实时数据源三优先级——原生 MCP 直调或脚本）；
5. **算价**【实时】：`calculate-price`（items 用 **productCode**+quantity；单位**分**→元；takeWayList 呈现取餐方式；items 还支持 couponId 券后实算与 modification 特制选项）。无实时数据源用快照价（实测两源一致可互为校验）；
6. **呈现**（字面模板见下）；
7. **用户选定**优惠方案后 → `memory.py record` 记账（实付+营养+记忆条目）；
8. （启用下单时）确认门 → `create-order` → 回报订单号。

## 外送（家/公司）

先 `delivery-query-addresses`（仅会话无地址时；列出已有地址供选，缓存 addressId）→ `delivery-query-stores`（地址→可送门店）→ 之后全链 orderType=2。新建地址走确认门（`delivery-create-address`，展示字段→确认）。

## 部门大单（双路径）

- **默认：普通大单**（beType=1）——菜单快照 + 官方搭配规则 + calculate-price；
- **官方团餐路径**（仅用户明说"企业团餐/要满减/助餐"）：`query-promotions`（满减规则）→ 搭配 → `query-meal-assistance`（**必须在 calculate-price 之前**）→ 算价。

## 订单跟踪与对账（实时，按需触发）

- 用户问"订单到哪了/我已支付" → `query-order`；
- "上次那单"：**本地记忆优先**（memory.py query），本地无记录才 `order-list` 兜底；
- 月度对账：order-list 与本地台账比对，差异如实提示；
- 用户说"取消" → 展示可取消项+原因选项 → 确认 → `cancel-order`。

## 无实时数据源降级面（快照模式）

照常可用：解析/记忆/配餐（快照）/卡路里/老单/账本/月账单/公开活动（快照）/菜单问答。
不可用：实时价/个人券积分/下单/订单/外送——提示一句"配 MCD_MCP_TOKEN 可解锁实时价格与下单"即止。
出单价格标"快照价（日期）"——写具体日期就是诚实，不说"价格可能不准"这类含糊话。
